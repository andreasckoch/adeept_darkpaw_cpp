# Sensor Streaming And Desktop Viewer

## Availability Check

The current C++ codebase has confirmed support for:

- camera detection through `rpicam-hello`/`libcamera-hello`
- camera streaming command setup through `rpicam-vid`/`libcamera-vid`
- Raspberry Pi system telemetry such as CPU temperature from sysfs
- software/runtime telemetry such as heartbeat, packet counters, command state,
  camera stream state, and later robot-node safety state
- servo command/accepted state generated by this codebase

The original Adeept DarkPaw repository contains robot-side Python code and
mentions self-stabilization/PID tuning, which implies that some shipped stacks
may use attitude sensing. This C++ repository does not yet contain a verified
IMU reader, battery-voltage reader, ultrasonic/range reader, or Robot HAT ADC
interface. Those channels are therefore represented as optional telemetry names
and must be published as `unavailable` until a hardware reader is implemented
and verified on the actual robot.

Do not display optional channels as real sensor data unless their packet status
is `ok`.

## Telemetry Packet

Telemetry uses one scalar sample per UDP packet:

```text
SPIDER_SENSOR_V1 sequence_id timestamp_ms name value unit status
```

Examples:

```text
SPIDER_SENSOR_V1 1 123456 heartbeat 1 bool ok
SPIDER_SENSOR_V1 2 123456 system.cpu_temp_c 51.4 C ok
SPIDER_SENSOR_V1 3 123456 imu.accel_x 0 mps2 unavailable
```

Supported name families:

- `heartbeat`
- `camera.*`
- `runtime.*`
- `teleop.*`
- `network.*`
- `system.*`
- `servo.*`
- `imu.*` optional
- `battery.*` optional
- `range.*` optional

## Mac Viewer

Start the desktop viewer:

```bash
python3 desktop/spider_viewer/spider_viewer_server.py --open
```

Send mock telemetry for UI development:

```bash
./build-host/spider_sensor_telemetry_mock --host 127.0.0.1
```

On the Pi, stream available telemetry to the Mac:

```bash
./build-pi/spider_sensor_streamer --host <mac-ip>
```

The viewer renders:

- centered camera panel or configured video URL
- lower-right transparent controls overlay
- bottom live time-series panel
- latest telemetry values and connection age

## Camera Stream

Start a raw H.264 UDP camera stream from the Pi:

```bash
scripts/stream_camera_rpicam.sh --host <mac-ip>
```

The browser viewer cannot decode raw H.264 UDP directly. Use VLC/GStreamer or a
future WebRTC/GStreamer bridge to expose a browser-displayable URL, then pass it
to the viewer:

```bash
python3 desktop/spider_viewer/spider_viewer_server.py \
  --open \
  --video-url http://127.0.0.1:8080/video
```

## Implementation Locations

- `inc/sensor_telemetry.h`, `src/messages/sensor_telemetry.cpp`: packet schema,
  parsing, serialization, validation.
- `inc/telemetry_series.h`, `src/telemetry/telemetry_series.cpp`: rolling
  time-series buffers.
- `src/tools/sensor_streamer_main.cpp`: available Pi/system telemetry streamer.
- `src/tools/sensor_telemetry_mock_main.cpp`: host-side simulated telemetry.
- `desktop/spider_viewer`: Mac-side viewer app folder.
- `scripts/stream_camera_rpicam.sh`: Pi camera stream helper.
